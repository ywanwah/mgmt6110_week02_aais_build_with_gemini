## 2. My findings
Copy the block below once for each finding. One finding per problem.

### Finding 1
- Where: [Personal Simulator Tab]
- What I did, what I saw: [When I select each profile, it does not colour to indicate which profile I am at]
- Which heuristic: [1 - Visibility of System Status]
- Screen or system: [a screen issue. Checked to code. The profile buttons all share one fixed style, and the app never records which preset user chose, so there's nothing for the screen to highlight. The data and routes are working fine. The problem is entirely in what the user sees, which makes it front-end, not a system (back-end) problem]
- Severity, and why: [2, This would allow clearer indication to user which profile are they simulating]
- The repair: [The Profile Tab selected to work on will have a clear coloured highlight as indicator]

### Finding 2
- Where: [Tab navigation (all tabs)]
- What I did, what I saw: [Tabs aren't in the URL. There is no "Back" and will take user off the site, and reloading resets user to Overview. User also can't share a link to one particular tab.]
- Which heuristic: [3 - User control and freedom]
- Screen or system: [This one is a system issue. Nothing is wrong with how any screen looks. The problem is how the app handles navigation. It keeps the current tab only in memory and never puts it in the URL, so the browser's Back, Reload and link-sharing have nothing to work with. Fixing it means changing how the app tracks where users are, not restyling a screen.]
- Severity, and why: [2, This would allow clearer indication where users are navigating and enable user control to go back, reload with link-sharing]
- The repair: [Store the active tab in the URL, so each tab has its own address. Clicking a tab updates the address, Back and Forward move between tabs, reloading keeps user on the same tab, and user can copy and share a link to a specific tab. Any unrecognised address falls back to Overview]

### Finding 3
- Where: [The browser tab title]
- What I did, what I saw: [Brower tab description say "FinancialHub Markets… stocks, crypto, futures, forex" for what is actually a Singapore CPI dashboard.]
- Which heuristic: [2 - Match Between the System and the Real World]
- Screen or system: [This is a screen issue. The data and routes are fine. The problem is the wording the user sees in the browser tab, plus what appears in search results or chat previews when the link is shared. It's a one-file text fix in index.html]
- Severity, and why: [2, Frequency is high: Every visitor sees the tab title on every visit. Impact is low: It doesn't stop anyone from using the dashboard, since they can see it's a CPI tool once the page loads. Market impact is what lifts it above 1: When the link is shared on WhatsApp, Telegram or LinkedIn, the preview says "stocks, crypto, futures, forex", so people may not click, or may think it's a trading site. It also looks unfinished to a marker or employer.]
- The repair: [Change the page title and descriptions in index.html to match the product, e.g. title "Singapore CPI Dashboard" and description "Track Singapore's Consumer Price Index by category, see monthly trends, and estimate how inflation affects user's own household budget. Data from SingStat." Apply the same wording to the og:title and og:description tags so shared-link previews match.]

### Finding 4
- Where: [Personal Simulator Tab]
- What I did, what I saw: [The calculator uses sliders only. On a phone it's hard to set an exact amount like $4,350, and there's no box to type into. On the Personal Simulator tab, I tried to set my monthly spending to $4,350. The slider only moved in $250 steps, jumping from $4,250 to $4,500, so I couldn't enter my exact amount.]
- Which heuristic: [7 - Flexibility and efficiency; Error prevention]
- Screen or system: [This is a screen issue. The calculation itself works. The problem is the control users are given to enter their number, which is part of the interface]
- Severity, and why: [2, Impact is moderate. Users can still get a result, but it's based on a figure up to $125 off their real spending, and the whole point of the simulator is a personal estimate. On a phone, dragging a thin slider accurately is fiddly too.]
- The repair: [Add a number input box next to the slider, linked to it, so users can either drag or type an exact amount. Allow any whole-dollar value between $1,000 and $25,000. If someone types outside that range, show a short message rather than silently changing it. Make the slider handle larger on mobile so it's easier to drag.]


### Finding 5
- Where: [No help or guide instruction tab and information]
- What I did, what I saw: [Help or guide instruction tab and information missing from my site.]	
- Which heuristic: [10 - Help and Documentation]
- Screen or system: [This is a screen issue. Nothing is broken behind the scenes. The interface just doesn't give users any guidance, which is content and design on the page]
- Severity, and why: [2, Impact is moderate. Frequency is moderate. It affects every newcomer on their first visit, though returning users no longer need it. Impact depends on the screen. Nielsen's point is that the best interface doesn't need help at all, so a missing help button alone would only be a 1. It rises to 2 because your app uses terms like "CPI", "YoY", "Base Year 2024 = 100", "Laspeyres" and "weights", and the Personal Simulator asks users to adjust category weights with no explanation of what that means. As a first-time user, I wanted to know what the headline CPI figure means and how to use the category sliders in the Personal Simulator. I found no help button, instructions or explanation of terms like "YoY" or "weights".]
- The repair: [Add a small "?" or "How to use" button in the header that opens a short guide: what CPI is, how to read the headline figures, and a three-step "how to use the Personal Simulator". Put a short plain-English line under each tab heading (e.g. "Adjust the sliders to match how you spend, and see your personal inflation rate").]
